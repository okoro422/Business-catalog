System Architecture

Visual reference for the storefront, Supabase services, core data relationships, and the optional invoice-to-n8n workflow.

Based on the current repository implementation · November 2026

1. Application and service architecture

The website is a set of static pages. Trusted data access is enforced by Supabase policies and database functions, not by hiding the browser's public key.

Solid arrows: normal app requests. Dashed arrows: optional invoice automation. Supabase RLS and RPC functions are the access-control boundary.

2. Core data relationships

This simplified entity view shows the primary ownership and workflow links. The actual SQL files define additional columns, constraints, indexes, policies, and triggers.

Not every table is shown. See supabase-schema.txt, supabase-fixes.sql, and supabase-remaining-features.sql for the full definitions.

3. Order and invoice processing sequences

Boundary to secure: A webhook URL embedded in a public static page is discoverable. Before processing genuine invoices, place an authenticated server-side function/proxy between the browser and n8n; keep private credentials in server-side secret storage.
